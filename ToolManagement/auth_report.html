Executive summary

The ToolManagement layer is the tool plane behind tools.distributed.systems: a FastAPI registry + gateway over 2,500+ tools across 40+ backends, plus a fleet of native MCP fabric servers (search, research, publish, memory, swarm, timeline, video/doc QA, unit/integration/finance fabrics) launched per-port by a launchd supervisor locally and Modal in production. Prior to this run, authentication was a single shared operator bearer token and — critically — no per-subdomain scoping: any valid token worked on every service.

What the review found: an already-working OAuth 2.0/OIDC authorization server (oauth.py, "Sign in with Distributed" — PKCE, consent, userinfo, refresh tokens, durable DuckDB-backed revocation) and an Ed25519 warrant system (warrants.py — capability grants with constraints, attenuation, receipts) that were simply not wired as a unified transport-auth layer. No third-party IdP (Keycloak/Logto/Authentik) is needed; the strategy is finish and unify our own.

This run landed Phase 1 completely and verified it live: shared token verification, per-subdomain audience binding, scope enforcement, RFC 7662 introspection, production-grade secret policy, a single-source scope registry, and middleware armed across every native server — all additive, with zero behavior change to production until the operator sets environment flags.

Two defects caught by live e2e (not by unit tests)

1. Blanket loopback trust made enforcement a no-op. Single-host deployments (launchd supervisor on the Mac, docker-compose) reach the public surface over 127.0.0.1 — exempting loopback silently bypassed all auth on the most common topology. Every unit test was green while the actual server let unauthenticated requests through. Repair: loopback trust is now explicit opt-in (UNIFIED_LOOPBACK_TRUST=1); internal fabric-to-fabric calls should use minted service tokens instead.
2. Enforcement checked the derived audience string, not the canonical registry key. Tokens minted for unit_fabric were verified against distributed_unit (the string derived from SERVICE_NAME). Repair: the canonical cfg.audience from scopes.py is what's enforced; the derived string is only an alias-resolution input.

Calibration lesson: the deployment is exactly the environment where the middleware matters — the acceptance gate for this project is live server verification, not suite greenness. Both findings are recorded in the playbook.

Deployment flags (operator controls)

FlagEffect
UNIFIED_SHADOW=1Arms the middleware in log-only mode: deny-lines are recorded, all decisions unchanged. Arm per service; review the feed for false positives.
UNIFIED_ENFORCE=1Middleware enforces (401/403). Requires UNIFIED_SHADOW=1 arming and — for MCP spec compliance — a working issuer URL for the 401 challenge.
UNIFIED_LOOPBACK_TRUST=1Opt-in only. Blanket loopback bypass. Do not set on single-host deployments where the public surface is loopback-reached; use minted service tokens for internal calls.
UNIFIED_AUDIENCEOverrides the derived audience label for a service (rarely needed now that resolve() aliases the observed names).
UNIFIED_INTROSPECTION_URLPoints services at the IdP introspection endpoint for revocation checking (60s cache).
TOKEN_SECRETRequired explicitly in ENV=production (boot refuses otherwise). Dev-only derived fallback retained.
Rollout protocol — per subdomain, in order T06→T14 (TASKS.md): arm UNIFIED_SHADOW=1 → ≥1 day of shadow logs → review deny-lines against replayed legit traffic → flip UNIFIED_ENFORCE=1 → run the revocation drill (revoke token; verify rejection ≤60s or immediate local reject). The tools registry itself flips last — it hosts the issuer.

Residual risk & honest calibration

  • Nothing changed in production until you set the flags. Middleware is env-armed and off by default; every existing client (legacy 16-hex tokens, static bearer, password login) keeps working through the 30-day legacy-token window.
  • Introspection endpoint has no rate limiting yet (deferred to T25). It is fail-open on store errors by design — a store outage degrades to "no revocation propagation", logged.
  • Shadow review is operator-paced: T07–T14 flips require real-traffic deny-line review per service; the ⚠️ services (finance, integration, publish) additionally need tenant/BYOK-path review given the history in TENANT_CREDENTIALS_WIRING.md.
  • HMAC shared secret still exists until T15–T18 (JWKS). Rotation is currently a fleet-wide secret change; the P2 upgrade makes it kid-based and restart-free.
  • Two live-observed environment quirks recorded in scopes.py::_ALIASES (video_q&a from a verbatim & in a service name; distributed_unit naming) — if service names change, aliases may need updating.
